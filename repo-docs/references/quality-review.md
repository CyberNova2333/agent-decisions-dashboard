# 阅读质量审计

这是审计记录，用于检查指南是否传达了可操作的理解，以及还剩哪些风险。

## 读者模拟

| 检查问题 | 从指南得到的答案 |
| --- | --- |
| 主路径是什么 | 从 HTTP 保存议题到版本历史、幂等回执与只读核对 |
| 难点是什么 | 多阶段保存可能部分完成，重试身份和用户原话都不能丢 |
| 阶段如何衔接 | 读取目标与版本 → 固定请求身份 → 校验并保存 → 核对各阶段回执 |
| 失败和边界在哪里 | 单进程管理一份数据；标签、引用和台账一致性不证明实现已验证 |
| 如何验证理解 | 主流程末尾给出已有测试或检查入口；本轮未执行业务测试 |
| 从哪里改 | 代码地图逐项给出范围内目录、重要代码和验证位置 |

## 可证伪性与后续问题

证伪检查：如果同 ID 改 payload 能再保存、旧版本覆盖当前 Markdown，或 `after-write` 接受过期回执，这份解释就失效。应复查对应断言和处理代码，而非只看成功页面。

读者下一问：恢复旧快照后怎样再次保存？需单独追踪 `core/recovery.py` 及恢复回归，本指南不宣称已完整解释恢复协议。
